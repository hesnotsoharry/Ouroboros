## Goal

After Wave 12, the canon Workbench's terminal tab bars are fully interactive (spawn, close, rename, active-switch, maximize) with tab collections persisted per-project across relaunch, the tab-header text-overlap visual bug is fixed via truncation + tooltip, and the project rail's three switcher surfaces (outer rail chip, title-bar dropdown, inner-rail dropdown) gain a remove affordance backed by `removeProjectRoot`. Stale project paths (folders renamed or deleted on disk since the IDE last saw them) auto-detect on each launch via a new `files.pathExists` main-process IPC and render dimmed in all three surfaces with the same inline remove affordance, so the user can clean them up in one click instead of editing config files. Wave 11's deferred verification gates run as Phase 0 catch-up. Terminal split remains deferred to a future wave (D4). The `layout.canonWorkbench` flag still gates canon vs legacy; no Wave 15 cutover yet.

## Locked decisions (Phase 0 — ADR)

ADR file: `roadmap/wave-12-terminal-and-project-crud-chrome/wave-12-decisions.md` (scaffolded on validation pass — Phase 5 of this command).

Each decision below is drafted with the recommendation already framed per `~/.claude/rules/best-practice-spectrum.md`. **REQUIRES USER LOCK** marks decisions whose answer is not determined by the grounding — Cole's call before validation re-run.

1. **D1 — Tab persistence: per-project, extending Wave 10's `canonWorkbenchSessions` schema in-place (not a parallel key).** Schema shape evolves from `Record<projectRoot, { upper: SessionSlot, lower: SessionSlot } | null>` to `Record<projectRoot, { upper: TabCollection, lower: TabCollection } | null>` where `TabCollection = { activeTabId: string | null, tabs: TabState[] }` and `TabState = { id, label, sessionId, kind: 'cc' | 'shell', createdAt }`. Legacy Wave 10 single-slot shape gets a cold-start reset on first launch (per the Wave 9 → 10 D1 pattern; no migration, no data loss for production users because the canon flag is still default-off and only Cole has live data). *(emerging best practice — per-project scoping with cold-start over migration is now the canon Workbench pattern after Waves 9 and 10; D1 continues that doctrine. REQUIRES USER LOCK — the schema evolution is non-trivial and Cole may want a different shape.)*

2. **D2 — Auto-detect-stale UX: inline dimming + per-row inline remove (X) button on stale entries. NO launch-time prompt or banner.** Stale chips/rows render at 0.5 opacity with the X button always visible (vs the same X on healthy entries surfacing only on hover). User cleans up when they care; not interrupted at launch. *(industry standard — VS Code's "missing folder" pattern. REQUIRES USER LOCK — Cole may prefer a one-time launch prompt instead, especially if the cohort of stale paths is typically large.)*

3. **D3 — Tab rename UX: inline contenteditable on double-click; single-click selects/activates.** `Enter` or blur commits the rename; `Esc` cancels. Empty input reverts to prior label. Maximum length 40 chars (truncated with `…` after). *(industry standard — VS Code / Terminal.app / iTerm all do this. REQUIRES USER LOCK — Cole may prefer a modal or no-rename-at-all to keep scope tight.)*

4. **D4 — Terminal split: OUT of Wave 12 scope; defer to a future polish wave.** The Split button stays mounted but inert with `title="Split — coming in a future wave"` so the UI doesn't regress visibly. Reason: split introduces a new geometry (third terminal, possibly N terminals in a nested split tree) with its own state-shape decision that's orthogonal to "tab CRUD on existing frames." Bundling it would inflate Wave 12 substantially. *(scope-boundary call. REQUIRES USER LOCK — Cole may want split in if it changes the architecture significantly enough to inform tab state.)*

5. **D5 — Terminal maximize: IN scope. Toggle hides the other frame + divider entirely, gives active frame full center-pane height.** State lives in `Workbench.tsx` as `maximizedFrame: 'upper' | 'lower' | null`. Maximize state is ephemeral — does NOT persist across relaunch (always start in dual-frame view). Triggered from `TabBarControls.Maximize` button per-frame. *(industry standard. REQUIRES USER LOCK — Cole may want persistence across relaunch.)*

6. **D6 — Tab header text overlap fix: CSS-only — `text-overflow: ellipsis` + `overflow: hidden` + `white-space: nowrap` on `TabItem`'s label span, plus `title={tab.label}` for native tooltip on hover.** No layout rework. *(industry standard. NOT REQUIRES USER LOCK — pure mechanical fix.)*

7. **D7 — `pathExists` IPC scope: single function `pathExists(path: string): Promise<boolean>`.** Main handler uses `fs.promises.access(path, fs.constants.F_OK)` — returns `true` if accessible, `false` on any error (no throw, no distinction between "missing" and "permission denied" because both manifest as "user can't open it"). Renderer caches result for the session (re-checks only on explicit refresh trigger or after `addProjectRoot`). *(industry standard for path-existence APIs. NOT REQUIRES USER LOCK — tight IPC surface is the expected shape.)*

8. **D8 — Wave 11 `forceUnified-no-autoclear` follow-up REMAINS OPEN, OUT of Wave 12 scope.** Not project/terminal CRUD; tangentially related but orthogonal. *(scope-boundary. NOT REQUIRES USER LOCK — different surface.)*

9. **D9 — Wave 11 `fileviewer-modal-blocks-tree-swap` follow-up REMAINS OPEN, OUT of Wave 12 scope.** Needs Cole's UX pick between options A/B/C/D before any work; not a Wave 12 prerequisite. *(scope-boundary. NOT REQUIRES USER LOCK — different surface.)*

10. **D10 — Wave 13 pane-ID dependency NOT addressed in Wave 12, but tab state's `sessionId` field IS the right place for Wave 13 to attach the `OUROBOROS_PANE_ID` later.** When Wave 13 introduces `OUROBOROS_PANE_ID` env injection from `pty.spawn` (per Cole's confirmed architecture 2026-05-24), each `TabState` already carries the pty session id — that's the natural identity to forward to hooks and bind the sidebar against.
