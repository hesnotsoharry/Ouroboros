Workbench overhaul · v1.0

A terminal-first workbench
that wears glass without breaking it.

This document is the canonical implementation reference for the Agent IDE workbench redesign. Every dimension, token, component contract, and state transition described below matches the live mockup in workbench.html exactly. Implementations should treat both as a paired truth — if they ever disagree, both should be amended back into alignment.

01 Principles

Three rules above all. Any implementation choice that violates them is wrong, regardless of how good it looks.

01

The TUI is sacred

The Claude Code TUI runs inside xterm. We don't draw inside it, parse its scrollback, or intercept its keys. The workbench wraps the terminal — the terminal is never the workbench.

02

Hooks > parsing

Every rich-UI signal — current tool, files touched, diffs, context, errors — comes from Claude Code hooks (PreToolUse, PostToolUse, UserPromptSubmit, Stop). Never regex against terminal output.

03

Glass with a deeper well

The xterm canvas drops to rgba(6,8,16,0.62) with --terminal-canvas-opacity: 0.86 so the glass shell reads through it. The terminal becomes a deeper well in the glass, not a black hole punched through it.

The opacity reduction on the xterm canvas is what lets the underlying glass bleed through. Test: any glass element behind the terminal (a wash glow, a popover edge) should be faintly visible through the canvas.

CC TUI viewport rules

  1. Do not draw inside the terminal. Any UI on top of the terminal canvas (e.g., a permission overlay) must be a sibling, not a child of xterm.
  2. Do not parse scrollback. Every signal comes from hooks. See §11.
  3. Status line below the prompt box belongs to CC; we don't add chrome to it. The "✻ sonnet-4.5 · ⏵⏵ auto-accept on · NN% context left · esc to interrupt" line is the literal CC TUI status — render only what CC outputs.
  4. Prompt box styling (the rounded input at the bottom of CC) follows the .wb-cc-prompt spec: glass-soft bg, 1 px --stroke-inner, radius --r-md, 8 px margin from canvas edges. This is CC's own input area — we don't replace it; if the styling diverges it's because CC changed and we update.

Shell terminal body (lower)

Same tinted-well treatment as upper. No CC prompt or status line — just raw xterm content. Inputs at the bottom (e.g., a $ prompt) come from the shell itself.

09 Agent sidebar — 348 px

Right edge of the workbench. Glass-soft background. Contains five panels stacked vertically. Each panel is independently re-rendered by hook events; no panel needs the others to render.

Header (top, full width)

Status dot + session label (claude · main) + sub (5m 12s · 12 tool calls) + Stop button (red square icon) + Maximize button. Bottom border --stroke-faint.

① NOW block

The current tool call. Updates on every PreToolUse / PostToolUse hook.

  • Label "NOW" in --accent-hi.
  • Live duration pill (top-right): mono · animates seconds.
  • 28 × 28 px tool glyph (radius 8 · --accent-tint bg · 1 px --accent-edge).
  • Tool name + arrow + path (mono, 11 px).
  • One-line tool input or description in --ink-3.
  • Progress bar (3 px · gradient --accent → --accent-hi · accent glow). Indeterminate when duration is unknown.

② Context block

Token usage donut + numeric counts + session meta.

  • 56 × 56 SVG donut · radius 22 · stroke 4 px · accent stroke with drop-shadow(0 0 6px var(--accent)).
  • Centre: percent + "USED" caption.
  • Right column: "CONTEXT" label · 46.2k / 200k tokens mono · then ⏱ 5m 12s · $ 0.18 meta line.

③ Files touched

Sourced from PostToolUse events on Read / Edit / Write tools.

  • Label "FILES TOUCHED" + count.
  • Each row: file icon · path (mono, ellipsized RTL so the filename stays visible) · +N in success · −N in error · live dot if currently editing.
  • Active row (currently editing) gets --accent-edge border.

④ Latest hunk

Most recent diff applied. Source: Claude Code's PostToolUse for Edit with the diff payload, or git status delta.

  • Header: "LATEST HUNK" label · file path · line number anchor.
  • Body: 6–8 lines of unified diff with gutter (line numbers in --ink-4 · +/− signs in success/error · row backgrounds --success-tint / --error-tint).
  • Footer: Accept (accent button) · Reject (ghost-border) · Open (ghost-border with eye icon).
  • On Accept: hunk dismissed, NOW block continues.
  • On Reject: revert the change (file written back from prior content), tool call marked rejected.

⑤ Hook timeline

Reverse-chronological list of recent hook events.

  • Vertical 1 px rail on the left (gradient: --accent top → --stroke-faint bottom).
  • Each event row: 9 × 9 px node on the rail · tool glyph + name · duration mono · target path mono.
  • Prompts: italic quote, accent node.
  • Thinking: brain icon, purple node, duration.
  • Tools: status colors — success/warning/error/accent(running).
  • Running events: 8 px glow + 1.4 s pulse animation on node.
  • "View all" button at top-right opens a full-history view (out of scope for v1).

Adaptive cards rule (canonical for hook events)

This is treatment "B" from §6 of the canvas — selected as canonical.

  • Running tool: full glass card (10 px padding) with progress bar.
  • Most recent completed: full card.
  • Older completed: collapse to one-line summary at 0.7 opacity.
  • On hover of a collapsed line: re-expand to full card temporarily.

11 Hook event schemas

The workbench subscribes to Claude Code's hook stream. These are the event shapes the UI expects. Any hook that fires but doesn't match the schema is logged as a warning and ignored.

Subscription contract

The renderer subscribes via a single useHookSubscription hook in src/renderer/hooks/useHookSubscription.ts. The main process spawns CC with hook scripts that write JSON Lines to a socket; the renderer reads them and dispatches by hook_event_name.

// Common envelope on every event
interface HookEnvelope {
  hook_event_name: string;        // discriminator
  session_id: string;             // CC session uuid
  cwd: string;                    // working directory
  transcript_path: string;        // .jsonl on disk
  timestamp: string;              // ISO 8601
}

PreToolUse

interface PreToolUseEvent extends HookEnvelope {
  hook_event_name: "PreToolUse";
  tool_name: "Read" | "Edit" | "Write" | "Bash" | "Grep" | "Glob"
           | "WebFetch" | "Task" | "TodoWrite" | string;
  tool_input: Record<string, unknown>;
  // Hook script may return one of these to gate the call:
  decision?: "allow" | "block" | "request";
  reason?: string;
}

UI impact: push a new running entry into the hook timeline, set the NOW block, mark the matching tab's status dot live. If decision === "request": enter Awaiting state (§13).

PostToolUse

interface PostToolUseEvent extends HookEnvelope {
  hook_event_name: "PostToolUse";
  tool_name: string;
  tool_input: Record<string, unknown>;
  tool_response: {
    success: boolean;
    output?: string;
    error?: string;
    duration_ms: number;
    // Tool-specific fields:
    lines?: number;        // Read
    matches?: number;      // Grep
    files?: number;        // Glob
    diff?: UnifiedDiff;    // Edit / Write
    exit_code?: number;    // Bash
    stdout?: string;       // Bash
    stderr?: string;       // Bash
  };
}

interface UnifiedDiff {
  path: string;
  hunks: Array<{
    old_start: number; old_lines: number;
    new_start: number; new_lines: number;
    rows: Array<{ type: "add" | "del" | "ctx"; n: number; text: string }>;
  }>;
  adds: number;
  dels: number;
}

UI impact: update the matching hook timeline entry with status (success → green, exit_code > 0 → red), duration, and details (lines / matches / +adds / −dels). If the tool returns a diff, push it into Latest Hunk and Files Touched.

UserPromptSubmit

interface UserPromptSubmitEvent extends HookEnvelope {
  hook_event_name: "UserPromptSubmit";
  prompt: string;
}

UI impact: add a prompt node to the hook timeline (italic, accent node). Transition session to thinking state.

Stop

interface StopEvent extends HookEnvelope {
  hook_event_name: "Stop";
  reason?: "complete" | "interrupted" | "error";
  message?: string;
}

UI impact: NOW block clears; session transitions to done for ~3 s then to idle. If reason === "error", transition to errored with the message.

SubagentStop

Same shape as Stop but for sub-agent (Task tool) completion. Hook timeline shows the spawned-thread converging back to its parent.

Notification

interface NotificationEvent extends HookEnvelope {
  hook_event_name: "Notification";
  title: string;
  message: string;
  level: "info" | "warning" | "error";
}

UI impact: bell icon shows a badge; clicking opens the notification center (the panel design lives in the existing design system).

Every CC session is in exactly one state at a time. The state determines the agent globe appearance, the status dot in the rail and tab bar, and which sidebar panels render which content.

Cross-state UI rules

  1. Awaiting blocks the session: no other hook events are processed for that session until resolved.
  2. Errored persists across re-prompts; clearing requires explicit user dismiss or a successful subsequent tool call.
  3. Disconnected (hook stream lost) is a meta-state that overlays any session state: sidebar dims, banner appears, last-known values stay visible but stale.

Audit

Every approval/denial writes a line to ~/.agent-ide/audit.jsonl:

{
  "ts": "2026-05-21T14:32:34.812Z",
  "project": "agent-ide",
  "session_id": "...",
  "tool_name": "Bash",
  "tool_input": { "command": "rm -rf node_modules && pnpm install" },
  "decision": "approve_once" | "always_tool" | "always_project" | "deny",
  "reason": "(optional user-provided note)"
}

Timeout

If the user is away for 5 minutes (no keyboard or mouse activity in the workbench window), the prompt auto-denies. CC receives blocked with reason "timeout". Configurable in settings.

  • Footer: "Hooks subscribed · waiting for events" (faint, with a layers icon)

Sidebar · idle (session live · nothing happening)

  • Header: idle dot · "claude · main" · "response sent · idle Ns"
  • NOW block at 0.6 opacity, content "Waiting for next prompt"
  • Context block + Files Touched persist (last known values).

Sidebar · errored (tool failed)

  • Header background tint rgba(248,113,113,0.05).
  • NOW becomes an error card: error-tint bg, error border, TOOL FAILED label, tool glyph + name + target, raw stderr in mono, dark bg.
  • Action row: Re-run · Open log.

Sidebar · disconnected (hook stream offline)

  • Header background tint rgba(248,113,113,0.05).
  • Banner under the header: 1 px error border · spinning ring · "Hook stream disconnected · reconnecting…"
  • All panels dim to 0.5 opacity, pointer-events: none.
  • NOW block sub-text changes to "last update Ns ago".

16 Responsive collapse

Below 1760 px the workbench progressively sheds chrome. The terminal pane is the last to give up space.

Breakpoints

≥ 1760Fullproject · inner · centre · agent (348)The hero design as drawn.

Collapse order (highest priority kept longest)

  1. Terminal never goes below 720 × 420.
  2. Latest Hunk diff (sidebar §4) collapses first.
  3. Agent rail narrows from 348 → 300.
  4. Project rail merges into inner (unified mode).
  5. Agent rail becomes floating HUD.
  6. Inner rail becomes a drawer (slide-in).

Tabs hold their ground

Terminal tab bars always render. Tabs may shrink to their status dot + project initial, but never disappear. They're the user's primary multi-session affordance.

18 Out of scope · what we explicitly removed

  • Dispatch screen (multi-session launcher). Discarded — user does not use it. DispatchScreen.tsx and its styles can be deleted along with related routes.
  • Chat-only shell. The old chat UI is gone. Terminal is now the primary input surface.
  • macOS traffic lights. This is a Windows-only build. Window controls are the Win10/11 minimize / maximize / close set, on the far right, 46 × 40 px, with the Windows red (#e81123) close-hover.
  • ⌘ symbols anywhere. Use Ctrl for keyboard shortcut labels.
  • Scrollback parsing of the CC TUI. Replaced wholesale by hook subscriptions (§11). The old CommandBlockOverlayBody.tsx regex logic must be removed.
  • Cards-only terminal treatment (option D in the canvas). Explored but not selected. Cards in the sidebar carry the rich-UI weight; the terminal stays a real terminal.
  • Floating HUD and bottom dock for the agent surface (canvas options B and C). Not in v1. The right rail is canonical. (HUD returns as the <1180 px responsive fallback in §16.)
